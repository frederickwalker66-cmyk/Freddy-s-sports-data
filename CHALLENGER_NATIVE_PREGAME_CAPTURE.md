# Challenger-001 native pregame probability receipt capture

Research only. The file `challenger_native_pregame_capture.py` **does not**
train a model, manufacture player features, use bookmaker-implied probabilities,
generate a player prop forecast, or modify frozen Champion-001.

## Why this exists

The existing live prospective archive contains event identities and a separate
**UNTRAINED fixed-rule baseline**. Neither is a trained Challenger-001 native
probability. The daily isotonic recalibrator must only see real, prospectively
recorded predictions from a sufficiently trained Challenger model.

This capture stage is now integrated into
`.github/workflows/challenger-prospective-pregame.yml`.
It runs after prospective ESPN schedule capture and untrained baseline
collection, and writes two artifacts inside `prospective_pregame/`:

- `native_challenger_forecasts.jsonl` (empty while prerequisites are absent)
- `native_forecast_capture_report.json` (explicit blocker or receipt counts)

Both travel in the existing immutable-ish GitHub run artifact to the
read-only calibration evidence review bridge. The SHA and same-run archive
metadata are integrity/attestation aids, **not independent verification**.

## Inputs

The following three inputs are **separate**, and the last two do NOT
currently exist in the automatic runner:

1. `prospective_pregame/prospective_event_evidence.jsonl`: genuinely captured,
   future ESPN NBA events; generated by the existing pregame workflow.
2. `challenger_results/nba_probability/research_model.json`: an actual
   reproducible Challenger NBA home-moneyline research model generated by
   `challenger_nba_probability.train_engine` from 200+ independently reviewed
   earlier training games and 50+ later holdouts. Its SHA and metadata must
   match the engine. **The repo currently has zero qualified NBA training
   examples and therefore no valid trained artifact.**
3. `prospective_pregame/nba_home_research_candidates.jsonl`: actual fresh
   candidate features with event identity, capture timestamps, feature
   publication and player availability sources, and the exact feature schema
   of the fitted model. Neither sportsbook odds nor retrospective final
   results may be used to fill features.

Candidates must include `event_id` equal to the **numeric ESPN event ID**
of the corresponding prospective snapshot; `home_team`, `away_team`,
`start_utc`, and `event_source_url` matching that snapshot; plus
`league="nba"`, `market_type="moneyline"`,
`selection_type="home"`, `snapshot_utc`, `features_asof_utc`,
`availability_checked_at_utc`, `availability_reviewed=true`,
`feature_source_url`, `availability_source_url`, and numeric
`features` matching the trained model. The original engine enforces that
the player availability review was checked within two hours of the feature
snapshot; a boolean attestation is not independent authentication.

## CLI

```bash
python challenger_native_pregame_capture.py \
  --snapshots prospective_pregame/prospective_event_evidence.jsonl \
  --model challenger_results/nba_probability/research_model.json \
  --candidates prospective_pregame/nba_home_research_candidates.jsonl \
  --output-dir prospective_pregame
```

The command **succeeds with a truthful blocked report** when inputs are
missing, and cannot create synthetic forecasts or betting picks.
Inspect `native_forecast_capture_report.json`. Once genuine inputs become
available at the same run, it invokes the existing
`challenger_nba_probability.score_future_event` to record a real pregame
RESEARCH-ONLY probability. These receipts remain uncertified and
not eligible for isotonic fitting until independently authenticated and
linked to independently adjudicated final outcomes.

Run the synthetic-only tests:

```bash
python -m unittest discover -s tests -p 'test_challenger_native_pregame_capture.py' -v
```
