# Challenger-001 — Original ESPN response-byte evidence for eight-sport pregame schedules

## Failure mode and why this matters

The prior seven-day prospective collector saved derived ESPN schedule objects, request timestamps and per-sport coverage counts, but NOT the exact HTTP response JSON bytes. A timestamp or SHA of a reconstructed JSON report would not establish that the originally observed source contained a particular matchup at that time. This original-byte gap must be closed before even researching reliable chronological model features.

## Source custody implementation

1. The live CLI uses a separate original-wire ESPN fetcher that returns BOTH parsed JSON and untouched response bytes from the same bounded HTTPS request. It refuses empty or >5 MB responses and malformed JSON. The original source URL is the exact ESPN public scoreboard route for a specific Eastern date and league.
2. Each successful schedule date writes its untouched original bytes into `prospective_pregame/espn_original_schedule_bytes/{league}_YYYYMMDD.json` using exclusive new-file creation, never overwriting an earlier capture. The date/league form is generated from the requested source slot and never from untrusted file names.
3. The research `espn_schedule_capture.json` records the archive file name, SHA-256, byte length, actual request start, actual HTTP completion time and exact league/day source URL. Every accepted game receives its parent source SHA; the archived per-event research row also carries the same source SHA without claiming publisher-signed data.
4. A second, independent local verification stage opens EVERY original response file successfully retrieved within the bounded eight-sport scan. It checks original raw SHA/length, validates its parsed games anew against the real per-request completion time and requested Eastern date, and requires exact equality between the originally returned eligible events and the derived schedule. Any missing, modified, truncated, wrong-source, missing-SHA, orphaned, or path-traversal source reference fails the entire research coverage audit.
5. Failed HTTP requests remain explicitly `unavailable` and do not have invented raw source files, game IDs, odds, or player availability. Source responses with zero valid upcoming games still have original bytes preserved so a reported empty checked slate has supporting source evidence.
6. The scheduled all-sport workflow refuses to publish the research artifact unless the number of original response files whose SHA and contents verified equals the number of successfully retrieved source days. Offline legacy one-day fixtures can remain read-only without a raw archive, but they are never mislabeled as an original-byte complete live capture.

## Limits

The SHA is generated by our collector; ESPN did not independently cryptographically sign the source or certify its original historical publication timestamp. An original response stored by GitHub is strong same-run byte custody evidence, NOT a certified pregame model forecast, qualified historical training sample, official league game identity, authenticated sportsbook checkout odds, market-specific settled line, or verified active roster.

Tests: `python -m unittest discover -s tests -p 'test_challenger_eight_sport_original_schedule_bytes.py' -v`. Fifteen synthetic cases check every eight-league response, original newline-preserving bytes, source SHA tampering, missing file, forged event/team/start, path traversal, raw listing count, absent original bytes, mismatched parsed/wire representations, CLI audit and no certification.

Champion-001 remains frozen. Qualified original pregame model examples, certified Champion/Challenger picks, positive-EV betting selections, and automated wagers remain ZERO until separately verified.
